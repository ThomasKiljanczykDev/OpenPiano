# Releasing OpenPiano

## Release steps

1. Bump `MAJOR`/`MINOR`/`PATCH` in `android/build-logic/convention/src/main/kotlin/dev/thomas_kiljanczyk/openpiano/buildlogic/AppVersion.kt`.
   `versionCode = MAJOR * 10000 + MINOR * 100 + PATCH`;
   `1.0.0` is `10000`.
2. Add `fastlane/metadata/android/<locale>/changelogs/<versionCode>.txt` for every locale,
   at most 500 characters.
3. Verify locally:

   ```
   python3 fastlane/validate_metadata.py --version-code <versionCode>
   cd android && ./gradlew assembleFossDebug testFossDebugUnitTest :core:model:test detekt lint
   ```

4. Push, then run `Release (Android)` (`gh workflow run release-android.yml`) with `dry_run` on.
   Inspect the `release-artifacts-<version>` artifact.
5. Re-run with `dry_run` off.
   The workflow tags `v<version>` and creates the GitHub release.
6. Upload `OpenPiano-<version>-play.aab` from the GitHub release to Play Console.

## Workflows

| Workflow | Trigger | Effect |
|---|---|---|
| `ci-android.yml` | push to `main`, pull request | lint, detekt, metadata validation, both flavors, unit and instrumented tests |
| `release-android.yml` | manual | quality gates, signed APK and AAB per flavor, per-flavor symbols zips, tag, GitHub release |
| `cd-store-listing.yml` | manual | renders screenshots, uploads screenshots, feature graphic and icon to Play as a draft |
| `cd-baseline-profile.yml` | manual | regenerates the baseline profile, opens a PR when it changed |
| `cd-privacy-policy.yml` | push to `main` touching `PRIVACY.md` | publishes `PRIVACY.md` to GitHub Pages at `/privacy/` |

`release-android.yml` resolves the tag from `AppVersion.kt` and fails if it exists.
It fails when any APK or AAB is unsigned or carries the debug certificate.
Release notes are generated by `gh release create --generate-notes`.
Per-version store text lives in the fastlane `changelogs/` files.

`cd-store-listing.yml` uploads images only;
listing text is edited in Play Console.
`dry_run` (default on) has Play validate, then discard the edit.
Nothing ships until "Send for review" in Play Console.

## Deobfuscation

Release builds are minified and obfuscated by R8.
`play` crashes are deobfuscated by Crashlytics and Play Console;
the AAB carries its own mapping.
`foss` has no crash reporting:
decode a reported stack trace with the release's `OpenPiano-<version>-foss-symbols.zip`:

```
unzip OpenPiano-<version>-foss-symbols.zip
$ANDROID_HOME/cmdline-tools/latest/bin/retrace mapping.txt stacktrace.txt
```

`native-debug-symbols.zip` inside it holds unstripped `.so.dbg` files for `ndk-stack`.

## One-time setup

### Signing keystore

The keystore and `android/keystore.properties` are gitignored.
Losing the keystore blocks updates to every non-Play install.

```
keytool -genkeypair -v -keystore openpiano-release.jks -alias openpiano \
  -keyalg RSA -keysize 4096 -validity 10000
base64 -i openpiano-release.jks | pbcopy
```

Local signed builds read `android/keystore.properties`;
copy `android/keystore.properties.example`.
Without a keystore, release builds are unsigned.

### GitHub

Create the Environment `production` with a required reviewer.
Required reviewers need a public repository or a paid plan.
Add these secrets to it:

| Secret | Value |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | base64 of `openpiano-release.jks` |
| `RELEASE_KEYSTORE_PASSWORD` | keystore password |
| `RELEASE_KEY_ALIAS` | key alias |
| `RELEASE_KEY_PASSWORD` | key password |
| `PLAY_GOOGLE_SERVICES_JSON_BASE64` | base64 of the Firebase `google-services.json` |

Add these repository variables (Settings > Secrets and variables > Actions > Variables):

| Variable | Value |
|---|---|
| `GCP_WI_PROVIDER` | `projects/<number>/locations/global/workloadIdentityPools/github/providers/github` |
| `GCP_PLAY_SA` | `openpiano-play@<project>.iam.gserviceaccount.com` |

The keystore is decoded into `RUNNER_TEMP` and deleted in an `always()` step.

Repository settings:

- Settings > Pages > Source: GitHub Actions.
- Settings > Actions > General > Workflow permissions: allow GitHub Actions to create and approve pull requests.

### Firebase

Create a Firebase project for `dev.thomas_kiljanczyk.openpiano`.
Place `google-services.json` in `android/app/src/play/` (gitignored) and store it as `PLAY_GOOGLE_SERVICES_JSON_BASE64`.
Enable Crashlytics.

### Google Cloud (Workload Identity Federation)

No long-lived JSON key.

```
gcloud services enable iamcredentials.googleapis.com androidpublisher.googleapis.com
gcloud iam workload-identity-pools create github --location=global
gcloud iam workload-identity-pools providers create-oidc github --location=global \
  --workload-identity-pool=github --issuer-uri=https://token.actions.githubusercontent.com \
  --attribute-mapping=google.subject=assertion.sub,attribute.repository=assertion.repository \
  --attribute-condition="assertion.repository=='<owner>/<repo>'"
gcloud iam service-accounts create openpiano-play
gcloud iam service-accounts add-iam-policy-binding openpiano-play@<project>.iam.gserviceaccount.com \
  --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/<number>/locations/global/workloadIdentityPools/github/attribute.repository/<owner>/<repo>"
```

Invite the service account in Play Console > Users and permissions,
with permission to manage store presence only.

### Play Console

1. Create the app.
   Complete Data safety, content rating, target audience and the privacy-policy URL.
2. Play App Signing: choose "Use my own app signing key" and export `openpiano-release.jks` with Play's PEPK tool.
   The GitHub `play` APK and Play installs then share a signature and update each other.
3. Upload the first AAB manually to the internal testing track;
   the package name is registered only by a first upload.

### F-Droid

`fdroid/dev.thomas_kiljanczyk.openpiano.yml` is the recipe.
Its `prebuild` strips the `play` flavor's Firebase wiring and builds `assembleFossRelease`.
Fill the placeholders and submit it as `metadata/dev.thomas_kiljanczyk.openpiano.yml` in a merge request to <https://gitlab.com/fdroid/fdroiddata>.
F-Droid signs with its own key;
its APK does not update GitHub or Play installs.
